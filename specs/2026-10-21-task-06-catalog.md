# Spec: TASK-06 каталог, карта, карточка заведения
**Date:** 2026-10-21 · **Author:** Макс (`TASK-06.md`), спецификация Claude Code
**Research:** `thoughts/research/2026-10-21-task-06-catalog.md` · **Size:** L (этапы 1–12 без деплоя)

## Problem
В приложении только пустые экраны. Данные 165 ветклиник и 3 862 отзывов уже в Supabase, но пользователь не может их найти, увидеть на карте и прочитать отзывы на своём языке.

## Goal
Первая показываемая версия: каталог с поиском и фильтрами, карта с точками, карточка заведения с раздельными рейтингами и отзывами по правилам показа; работает на живой базе и в демо-режиме на фикстурах.

## Scope (из `TASK-06.md`)
### In Scope
1. Каталог (вкладка «Каталог»): карточки (название, район, Google-рейтинг и число отзывов, «Круглосуточно», «Позвонить» при наличии телефона); поиск по названию на трёх языках (регистр, простая транслитерация «Bay Vet» ↔ «Бэй Вет»); фильтры «Круглосуточно», район (9; по `area_ru`/`area_en`, поправка владельца 2026-10-21), «Есть телефон»; сортировка: рейтинг Google, число отзывов, расстояние (только при разрешённой геолокации); переключатель «Список / Карта».
2. Карта: Google Maps JavaScript API, маркеры из `lat`/`lng`, нажатие → нижнее превью с «Открыть»; кластеризация; центр Паттайя, «Рядом со мной» при геолокации; без ключа или при ошибке — заглушка и работающий список.
3. Вкладка «Рядом»: ближайшие (геолокация) или самые популярные (отказ).
4. Карточка заведения: шапка (название, район, категория, «Круглосуточно»), рейтинги (правило 5), «Позвонить» (`tel:`), «Маршрут» (Google Maps по координатам, новая вкладка/внешний браузер), «Сайт», «Поделиться» (Telegram); адрес; часы работы (разбор тайского формата в дни недели на языке интерфейса, иначе сырой текст); отзывы (правила 3–6): оценка, дата, автор, текст, подпись о переводе, «Показать оригинал/перевод», «Показать полностью», подгрузка по 10, сортировка «Новые / Сначала низкие оценки», фильтр по оценке; «Записаться или спросить» → окно «Скоро».
5. Состояния загрузка / пусто / ошибка на каждом экране; потеря сети — не белый экран.
6. Язык интерфейса: русский по умолчанию, английский переключателем, выбор запоминается; первый выбор — язык браузера/Telegram без `initData`.
7. Демо-режим: при пустых переменных окружения данные из `fixtures/catalog.sample.json`, баннер «Демо-данные».
8. Типы базы: ручные правки `src/types/database.types.ts` по разделу «Типы базы».
9. `.env.example`: `VITE_GOOGLE_MAPS_API_KEY` без значения.

### Out of Scope
Заявки и формы записи, вход через Telegram, LINE, SOS, «Товары», профиль питомца, платежи, любая запись в базу с клиента; вкладка «Записи» не меняется; данные OSM в каталоге.

## Правила показа (дословно из `TASK-06.md`, обязательны)
1. **Название заведения показывать как в оригинале, не переводя:** поле `name_original` (тайское и/или английское, как у источника). Рядом небольшая кнопка «По-русски» (в английском интерфейсе «In English»), которая по нажатию показывает `name_ru` (или `name_en`) с подписью «транслитерация»; повторное нажатие возвращает оригинал. Если `name_original` пусто, показывать `name_th`, затем `name_en`, затем `name_ru`. Поиск по названию ищет по всем четырём полям (`name_original`, `name_th`, `name_en`, `name_ru`). _(Замена правила 1, поправка владельца 2026-10-21.)_
2. **Язык интерфейса:** русский по умолчанию, английский переключателем; выбор запоминается. Для первого выбора можно использовать язык Telegram или браузера, `initData` не использовать.
3. **Текст отзыва:** сначала перевод на язык интерфейса (`text_ru` или `text_en`); если его нет (`null`), показывать оригинал `text` и подпись «Перевод скоро» (флаги `needs_ru` и `needs_en` показывают, что перевод ещё нужен). Если показан перевод, а не оригинал, подпись «Автоперевод». У каждого отзыва кнопка «Показать оригинал» / «Показать перевод» (мелкий, но видимый текст).
4. **Не показывать и не создавать шаблонных «переводов».** Если перевода нет, только оригинал с подписью.
5. **Два разных рейтинга не смешивать:** «Google 4,6 · 707 отзывов» (`google_rating`, `google_reviews_count`) и отдельно «Собрано отзывов: 81, средняя оценка 4,7» (`venue_review_stats`). Всё подписано, откуда цифра.
6. **Автор:** показывать `author_display` как есть (имя и инициал или ник), без ссылок на профили.
7. **Данные OSM** в каталоге не используются. Подпись «© участники OpenStreetMap» нужна только если на экране появятся данные из OSM.
8. Тексты отзывов недоверенные: выводить только как текст, никогда как разметку.

## Acceptance Criteria (дословно из `TASK-06.md`)
- [ ] В режиме фикстур и в режиме базы (если доступ есть) каталог показывает заведения, поиск и фильтры работают, тесты на каждый фильтр и на порядок сортировки.
- [ ] Название, текст отзыва и подписи следуют правилам показа 1–6; тесты покрывают: перевод есть, перевода нет, оригинал совпадает с языком интерфейса, переключатель «Показать оригинал», длинный текст.
- [ ] Рейтинг Google и средняя оценка по собранным отзывам показываются раздельно и подписаны.
- [ ] Карта: маркеры из координат, превью по нажатию, заглушка без ключа (тест), сборка не содержит ключей.
- [ ] Отзывы подгружаются страницами, в браузер не попадают лишние данные.
- [ ] Скриншоты 390×844 (каталог, фильтры, карта, карточка с переведённым и непереведённым отзывом, английский интерфейс) показаны в чате.
- [ ] lint, typecheck, test, build, npm audit без ошибок; CI зелёный; отчёт по разделу 10 ТЗ.

## Constraints
- `CLAUDE.md` → `TZ-bulletproof_1.md` → `TASKS.md`; секреты только в env, `service_role` в клиенте недопустим; mobile-first, 44 px, состояния на каждом экране; строки интерфейса в файлах локализации; внешние данные недоверенные.
- Производительность: 165 заведений одним запросом; отзывы по заведению страницами по 10; кеш в памяти на сессию; не тянуть все отзывы.
- Дизайн-система прототипа (фон `#F5F4F0`, карточки белые, граница `#E4E2DC`, радиус 16–18, зелёный `#0B6B58`, светлый `#E3F0EC`, текст `#15171A`, второстепенный `#5B5F66`; Manrope/Onest).

## Non-Goals
Из «Чего НЕ делаем в Demo v0» и «Что не входит»: свой магазин, аптека, телемедицина, ситтеры, предоплата, нативное приложение; заявки, вход, LINE, SOS, «Товары», профиль питомца, платежи, запись с клиента; шаблонные «переводы».
