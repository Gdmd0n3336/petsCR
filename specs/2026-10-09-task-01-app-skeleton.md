# Spec: TASK-01 каркас приложения
**Date:** 2026-10-09
**Author:** Макс (задача из `TASKS.md`), спецификация Claude Code
**Research:** `thoughts/research/2026-10-08-task-01-app-skeleton.md`
**Size:** M (этапы 1–10)

## Problem
Кода приложения нет. Все следующие задачи (импорт OSM, каталог, карта, вход через Telegram, LINE) должны строиться на одном настоящем каркасе с проверками, иначе каждая задача будет заново решать сборку, типы, тесты и CI.

## Goal
Пустой, но настоящий каркас Lapa: одна кодовая база React + TypeScript, которая открывается и в Telegram, и в обычном браузере, с работающими `lint`, `typecheck`, `test`, `build`, `dev` и CI на каждый push.

## Scope

### In Scope (из `TASKS.md`, «Что сделать»)
1. Репозиторий: React + TypeScript (сборщик выбрать по документации, объяснить выбор в 2 строках), линтер, форматтер, проверка типов, тест-раннер.
2. Скрипты `lint`, `typecheck`, `test`, `build`, `dev`.
3. Подключение Telegram WebApp SDK с безопасным поведением вне Telegram (в обычном браузере приложение открывается и работает).
4. Клиент Supabase, конфигурация через переменные окружения (`.env.example`).
5. Страница-заглушка «Lapa» с нижним меню из пяти вкладок: Рядом, Каталог, Записи, Товары, Питомец (пустые экраны с состояниями загрузки / пусто / ошибка).
6. Файл локализации с русскими строками.
7. CI на каждый push: lint, typecheck, test, build.

Добавлено (решения Макса от 2026-10-09):
8. Версия Node зафиксирована (`.nvmrc` и `engines`), CI на Node 22.
9. TypeScript закреплён на `~6.0.x` с записанной причиной и условием пересмотра.

### Out of Scope
- Роутер (добавляется в TASK-06).
- Данные заведений, карта, каталог, авторизация через Telegram (TASK-03…TASK-07).
- Запросы к таблицам Supabase и сгенерированные типы БД (TASK-02-sync).
- Деплой и хостинг (этап 12, только по просьбе Макса).
- PWA (манифест, service worker).

## Constraints
- Приоритет документов: `CLAUDE.md` → `TZ-bulletproof_1.md` → `TASKS.md` → `SKILL.md`.
- Версии и API библиотек сверяются с актуальной документацией (Context7, затем официальные docs, плюс `npm view` для peer-зависимостей).
- Секреты только в переменных окружения; в браузер попадают только `VITE_*` переменные; ключ `service_role` никогда не используется в клиенте.
- Минимальная сложность: никаких абстракций «на вырост», state-менеджеров, UI-китов, роутера.
- Mobile-first, тач-зоны от 44 px, состояния загрузка / пусто / ошибка.
- Дизайн-токены прототипа (README): фон #F5F4F0, карточки белые с границей #E4E2DC и радиусом 16–18, зелёный #0B6B58, светлый зелёный #E3F0EC, SOS #C8322B, текст #15171A, второстепенный #5B5F66; шрифты Manrope (заголовки), Onest (текст).
- Внешние данные недоверенные (в каркасе их нет, но обёртка Telegram не исполняет launch params как код).

## Non-Goals (из «Чего НЕ делаем в Demo v0», `CLAUDE.md`)
- Свой магазин, аптека, телемедицина, ситтеры, предоплата, нативное приложение, автоподтверждение записи нейросетью.
- «Товары», профиль питомца, «Что делать?» здесь только экраны-заглушки (в этой задаче все пять экранов пустые; пометка «скоро» для «Товары» и «Питомец»).
- Платежи.
