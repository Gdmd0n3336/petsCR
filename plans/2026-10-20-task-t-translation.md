## Challenge Log (этап 3)
**Способ перевода.** Выбрано: подагенты Workflow, 50 пакетов (≤ 100 отзывов, ≤ 9 000 знаков), конвейер на пакет: перевод → независимая проверка смысла/тона → повторный перевод расхождений → повторная проверка. Альтернативы: (1) скрипт с API Anthropic — нет ключа в окружении, и ключ потребовал бы остановки по условию (а); (2) машинный переводчик (Google/DeepL) — платный сервис с ключом и хуже держит тон и разговорную речь; (3) один агент последовательно — не уложится в контекст и в «сегодня».
**Формат обмена.** Агент читает `data/work/batches/b-NNN.jsonl`, пишет `data/work/out/b-NNN.json` и сам запускает `scripts/translate/check-batch.mjs` (проверки 1–2) до «OK». `source_url` агент не копирует — сборка берёт его по id из входа (исключает искажение длинных ссылок).
**Проверка 5.** Отдельный агент (другой контекст, не видит рассуждений переводчика) по каждому отзыву пакета даёт вердикт yes/no «соответствует ли перевод оригиналу по смыслу и тону» с упором на 1–2★, звучащие положительно, и 5★, звучащие резко негативно; пишет `data/work/verify/b-NNN.json`, проверяет `check-verify.mjs`. Все «no» переводятся заново с учётом причины (`data/work/fix`), затем новый агент проверяет их (`data/work/reverify`). Порог остановки: > 3% «no» после повторного перевода.
**Проверки 3–4** — в `assemble.mjs` (длина 0,4–2,5 для оригиналов ≥ 20 знаков; дубли длинных > 40 знаков переводов у разных оригиналов).
**Стоимость.** Подагенты расходуют лимит подписки Claude этой сессии, отдельного счёта нет; в отчёте — токены и эквивалент по тарифам API.
